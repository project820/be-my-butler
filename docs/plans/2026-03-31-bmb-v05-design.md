# BMB v0.5 Design — Pipeline Redesign with Codex Plugin Integration

## Context

BMB v0.4.0's 12-step pipeline was built around tmux pane orchestration and `codex exec` CLI invocation. This architecture emerged from Codex's instability (100% timeout rate in v0.3.x), requiring elaborate fallback/degradation systems, blind verification, and a persistent Consultant agent for real-time monitoring.

With the Codex Claude Code plugin (companion + AppServer protocol), the root causes of instability are eliminated. This redesign replaces the heavy orchestration with a lighter, more reliable pipeline that leverages existing Claude Code infrastructure (/btw, /simplify, /last30days, Codex companion).

**Core change**: Codex writes code, Claude verifies — structural cross-model verification by design.

---

## 1. Core Architecture

### Sandwich Pattern
```
Heavy (Opus)  →  Light (Sonnet/Codex)  →  Heavy (Opus)
 설계/검증         리서치/구현              리뷰/회고
```

### 5 Principles
1. **Cross-model verification is structural** — Codex codes, Claude reviews (always different family)
2. **Retrospective is sacred** — Steps 10-11 never skip
3. **Dynamic difficulty routing** — mini for simple, High for complex, Sonnet on escalation
4. **Main session protection** — Agent tool + external process isolation
5. **Leverage existing infrastructure** — /btw, /simplify, /last30days, Codex companion

### Model Assignment

| Role | Model | Rationale |
|------|-------|-----------|
| Lead/PM | Opus 4.6 | Metacognition, orchestration |
| Architect | Opus 4.6 | Design is a metacognition battle |
| Researcher | Sonnet 4.6 | Fast info gathering, sufficient quality |
| Coder (default) | GPT-5.4 mini | Simple tasks, cost efficient |
| Coder (complex) | GPT-5.4 High | Multi-file, architecture changes |
| Coder (escalation) | Sonnet 4.6 | After 2+ rejections |
| Verifier | Opus 4.6 | Different family from coder |
| Tester | Opus 4.6 | Independent from coder |
| Writer | Sonnet 4.6 | Docs don't need Opus |
| Analyst | Opus 4.6 | Bird's Law analysis |

### Multi-Agent Role Assignment Advisory v1.0
- PM/Architect → strongest model (Opus). Design is a metacognition battle.
- Coder → mini-class for single functions/boilerplate. Multi-file refactoring requires upgrade.
- Reviewer/Verifier → MUST be different model family from coder. Same family = self-preference bias.
- Escalation Rule → 2+ rejections or changed files ≥3 → upgrade coder to Sonnet immediately.
- Never do → Put mini in reviewer/PM role. Weak judges pass bugs.
- Tester → separate agent. Coder testing own code drops pass@1 by ~10%.
- Cost optimization → difficulty-based dynamic routing, not fixed cheap model.
- Heavy→Light→Heavy (sandwich) is default, but monitor the Light tier's difficulty ceiling.

## 2. Pipeline Steps

```
1.  Setup (Opus Lead)
2.  Brainstorm + /btw (Opus Lead)
3.  User Approval
4.  Architecture (Opus Architect subagent)
5.  Pre-Research (Sonnet + /last30days)
6.  Implementation (Codex companion)
7.  Review (Opus Verifier subagent)  → reject: loop to 6
8.  Testing (separate agent)
9.  /simplify + Docs (Sonnet Writer)
10. Analyst Retrospective (Bird's Law)
11. Lead Retrospective — NEVER SKIP
12. Commit/Push/Cleanup
```

### Step 1: Setup (Opus Lead)
- Session init, config load, incident spool import
- Check previous session carry-forward
- No Consultant pane, no Monitor

### Step 2: Brainstorm (Opus Lead + /btw)
- Lead talks directly with user
- User can /btw for side questions anytime
- Output: `.bmb/handoffs/briefing.md`

### Step 3: User Approval
- Present briefing, get go/no-go

### Step 4: Architecture (Opus Architect subagent)
- `Agent(subagent_type="bmb-architect")`
- Solo design, no council debate (Review catches design issues in Step 7)
- Must include `complexity: low | high` rating in output
- Output: `.bmb/handoffs/plan-to-exec.md`

### Step 5: Pre-Research (Sonnet subagent)
- `Agent(model="sonnet")` with /last30days skill
- Targeted research based on plan-to-exec.md
- Output: `.bmb/handoffs/research-results.md`

### Step 6: Implementation (Codex companion)
- Lead reads plan-to-exec.md complexity rating
  - `low` → `--model gpt-5.4-mini --effort medium`
  - `high` → `--model gpt-5.4 --effort high`
- Invocation: `Bash("node $COMPANION task --write --model $MODEL --effort $EFFORT 'prompt'")`
- 3-tier fallback on failure:
  1. Retry (same command)
  2. `--resume-last` (continue from where it stopped)
  3. Sonnet escalation: `Agent(model="sonnet")` takes over coding
- Output: code changes in repo + `.bmb/handoffs/impl-result.md`

### Step 7: Review (Opus Verifier subagent)
- `Agent(subagent_type="bmb-verifier")`
- Combined code quality + design fitness review
- PASS → Step 8
- REJECT → loop to Step 6
  - Track rejection count
  - 2+ rejections OR 3+ changed files → escalate coder to Sonnet 4.6
  - `bmb_learn MISTAKE` on rejection

### Step 8: Testing (separate agent)
- `Agent(subagent_type="bmb-tester")`
- Independent from coder (structural separation)
- Not blind pair — single comprehensive test pass
- Failure → loop to Step 6 (test failures count toward REJECTION_COUNT for escalation)

### Step 9: /simplify + Docs
- Lead invokes /simplify skill (code cleanup)
- `Agent(subagent_type="bmb-writer", model="sonnet")` for docs update
- Re-verify after simplification (revert on test failure)

### Step 10: Analyst Retrospective (Opus Analyst subagent)
- `Agent(subagent_type="bmb-analyst")`
- Query analytics.db
- Bird's Law severity analysis (critical/warn/info)
- Pattern identification, promotion candidates
- Output: `.bmb/handoffs/analyst-report.md`

### Step 11: Lead Retrospective (Opus Lead)
- Read analyst report
- Integrate learnings: `bmb_learn` calls
- Write session-prep.md for next session continuity
- **RULE: This step MUST execute. Pipeline cannot end without it.**

### Step 12: Commit/Push/Cleanup
- Git commit and push
- Session archive

## 4. Codex Companion Invocation & Escalation

### Companion path resolution
```bash
# In Lead's session, CLAUDE_PLUGIN_ROOT is available
COMPANION="${CLAUDE_PLUGIN_ROOT}/scripts/codex-companion.mjs"

# Fallback: direct search
if [ -z "$COMPANION" ] || [ ! -f "$COMPANION" ]; then
  COMPANION=$(find ~/.claude/plugins/cache/openai-codex -name codex-companion.mjs 2>/dev/null | head -1)
fi
```

### Invocation pattern
```bash
node "$COMPANION" task --write \
  --model "$MODEL" --effort "$EFFORT" \
  "$(cat <<'EOF'
<task>
Read .bmb/handoffs/plan-to-exec.md and .bmb/handoffs/research-results.md.
Implement the design as specified.
Write completion summary to .bmb/handoffs/impl-result.md
</task>
EOF
)"
```

### 3-tier fallback
```
Attempt 1: node companion task --write ... (normal)
  └─ fail → Attempt 2: node companion task --write ... (retry)
       └─ fail → Attempt 3: node companion task --write --resume-last ...
            └─ fail → Escalation: Agent(model="sonnet", prompt="Implement...")
```

### Escalation controller (Lead logic)
```
REJECTION_COUNT = 0
CURRENT_MODEL = config.model_routing.coder_default  # or coder_complex

loop:
  Step 6: Implementation(CURRENT_MODEL)
  Step 7: Review

  if REJECT:
    REJECTION_COUNT++
    bmb_learn MISTAKE ...
    if REJECTION_COUNT >= escalation_threshold OR changed_files >= complex_file_threshold:
      CURRENT_MODEL = "sonnet"
      log "ESCALATION: coder upgraded to Sonnet 4.6"
    goto Step 6

  if PASS:
    goto Step 8
```

### Incident recording
- Companion failures recorded to NDJSON spool (same as before)
- Lead records: `bmb_analytics_event` on each attempt/failure/escalation
- Analyst reads these in Step 10

## 6. Verification Plan

1. **Companion smoke test**: `node companion task 'echo hello'` → success
2. **Model routing**: Verify mini/high/sonnet models respond correctly
3. **Fallback chain**: Simulate failure → retry → resume → escalation
4. **Agent dispatch**: Each subagent (architect, verifier, tester, writer, analyst) spawns and returns results
5. **Handoff flow**: Files created at each step, read by next step
6. **Escalation**: Force 2 rejections → verify Sonnet upgrade triggers
7. **Retrospective**: Verify Steps 10-11 execute and produce analyst-report.md + session-prep.md
8. **Full pipeline**: Run complete 12-step on a test task
